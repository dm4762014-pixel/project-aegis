What changed for this laptop

One small model, on CPU

A dedicated loopback Ollama instance and isolated model store keep this profile separate from other model sessions.

Small working context, immediate release

512-token context, two CPU threads, small batches, one inference at a time. New work waits up to eight seconds for RAM at or below 89%, leaving a margin below the 90% recovery threshold. The model unloads after generation; cached answers remain available.

The safeguard stays on

The 90% RAM threshold remains active. Unrelated applications stay open. If memory is too tight, the gateway reports a refusal rather than pretending the request succeeded.

Limits and provenance

Live model runs and benchmark timings come from this Windows laptop. Model quality is limited. Passing a short benchmark is not a sustained-load test, proof of a distributed cluster, or a guarantee against system freezes. The traffic score is a request-pattern proxy, not a psychological assessment.

Recovery fault tests use a mocked upstream and injected RAM readings, clearly labeled simulated. The demo does not fill physical RAM or reset network adapters. Context-switch and disk counters include other programs; gateway page faults do not describe the separate model process.

The launcher may download the 105 MB SmolLM2 model on first use. Installed-model inference is local. No prompts are sent to a cloud AI API.
