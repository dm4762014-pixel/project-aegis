    What this checks—and what it cannot tell you

    Clicking Check makes small requests to example.com, Cloudflare’s 1.1.1.1:443, and Microsoft’s connectivity-test endpoint. Those services receive normal connection metadata. HTTP portal redirects are never followed.

    Checks use this laptop’s network and system resolver with direct connections; a browser proxy, VPN, firewall, or a blocked destination can give different results. Virtual adapters may count as active. A possible DNS problem or sign-in portal is a hypothesis, not a confirmed diagnosis. This does not measure Wi-Fi signal quality, bandwidth, or every app’s connectivity.

    No admin access, login, AI model, or settings changes. Reports omit adapter names, local IP addresses, Wi-Fi names, portal URLs, and response content. There is no cloud report upload. Download only when you want a local copy.

    Is a specific service reachable?

    Check your learning portal, GitHub, or another public HTTPS service. See exactly which stage responds. No login, redirects, or response content is collected.

    Reports include your chosen computer label and the full URL path. Use anonymous labels and no sensitive URLs. Use the same exact URL on each computer. No passwords, query parameters, private IPs, or internal-only sites. Checks use direct connections; your browser’s proxy may differ.

    Compare reports from different computers

    Run the app and download a service report on each computer. Import 2–12 reports for the same service here. Files are processed by this local app, with no cloud upload.

    Reports and device names are self-reported, not authenticated. Multiple browser profiles on one computer are not multiple verified computers. Compare timestamps and networks before drawing conclusions.
